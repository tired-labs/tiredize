# Contributing

## Overview

How changes reach tiredize: what a pull request needs and how it is
reviewed. A contributor-facing guide does not exist yet.

## Rules

- **Every pull request is tied to an open issue** that states the
  problem. Minor bug fixes are exempt.
- **Review happens on the pull request.** Work done by agents in the
  repository is accepted there by the maintainer, who opens the pull
  request after the branch is pushed. Pull requests are squash-merged.
- **Contributors may edit the wiki.** A wiki change is reviewed like
  code, not discarded and rewritten.
- **A change outside an issue's scope** is folded in only when the
  maintainer decides so.

GitHub Copilot review is also used on pull requests in practice.

## Design Decisions

- **The minor-fix exemption stays,** because requiring an issue for a
  typo adds friction for no gain.
- **Contributors may edit the wiki** even though agents follow the
  dotclaude templates, accepting that a contributor's page may not match
  them until review.
